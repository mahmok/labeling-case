02 · Assumptions

What I took as given

Each of these shaped a design decision.

1

The printer name is the primary key at the vendor.

2

“Query” means granular filtering and search, not just listing.

3

A label's primary key is its ID, not ID + version.

4

The vendor has API rate limits.

03 · Solution

High-level solution

The design keeps a synced copy of vendor data next to its metadata. A sync service keeps the two up to date.

09 · Deployment · Option 1

ECS + RDS + S3 / CloudFront

Two ECS services in a VPC. A public load balancer routes to the API. The UI is static on S3 behind CloudFront.

10 · Deployment · Option 2

Serverless: Lambda + API Gateway + EventBridge

No always-on containers. EventBridge schedules run the jobs, and RDS Proxy keeps database connections in check.

11 · Ideas

Things I thought of implementing

Two ideas I considered but haven't built yet.

🔗

Store references, federate the rest

Keep IDs and metadata. Fetch extra vendor details through their APIs when they're needed.

🆔

UUIDv5 IDs from vendor data

Derive IDs from a namespace and vendor data, such as the printer name. Re-running a sync then gives the same IDs.

12 · Next steps · 1 of 2

Things I would add or change

Security, data integrity, events and structure.

🔐

Auth

  • Entra / OpenID sign-in
  • Machine-to-machine APIs
  • A separate database user per scope (today: one)
🧾

Drift detection

  • Checksums per record
  • Merkle / hash trees for whole datasets
📣

Event streaming

  • The worker polls today
  • Emit business events: printer synced, print submitted, job failed
📦

Packages

  • One package per bounded context
  • One app directory per entry point

13 · Next steps · 2 of 2

More things I would change

Smaller changes that pay off quickly.

💾

Job checkpoints

Save progress as a job runs, so a failed job resumes instead of restarting from scratch.

🎛️

Granular sync

Turn creates, updates and deletes on or off, or pick a subset.

⚡

Sync on demand

Sync a printer when a print can't find it.

🎭

Playwright

End-to-end tests for the UI.

🗄️

Job data retention

Delete old job rows and results after a set period, so the jobs table stays small.

🤖

MCP server

Let AI assistants query and print through the same use cases.
